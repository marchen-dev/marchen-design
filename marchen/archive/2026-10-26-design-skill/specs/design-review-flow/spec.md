## 目的

检查 UI 代码是否符合 marchen-design 的规则，给出可执行的问题清单。可由用户主动调用，也可在 design skill 完成改动后用于自查。

### 需求: 审查范围

审查 MUST 默认只针对本次改动涉及的 UI 文件（当前 git 工作区的改动，或用户指定的文件 / 目录）；用户明确要求时 MAY 审查整个目录。

#### 场景: 默认范围

- **GIVEN** 工作区中改动了两个页面文件
- **WHEN** 用户调用 design-review，未指定范围
- **THEN** 只审查这两个文件

### 需求: 自动检查

审查 MUST 先运行插件自带的 lint-design 脚本扫描审查范围，并把违规项（文件、行号、规则、违规写法）纳入结果。

#### 场景: 发现渐变

- **GIVEN** 审查范围内的文件中使用了 `bg-gradient-to-r`
- **WHEN** 运行 design-review
- **THEN** 结果中包含该文件、行号和"禁止渐变"

### 需求: 人工清单检查

自动检查之后，审查 MUST 对照清单检查正则无法判断的项，至少包括：一屏是否只有一个主操作且为 default 变体；强调色是否只用于状态；是否手写了 marchen-design 已提供的组件或区块；是否用 className 覆盖了组件的颜色、圆角或阴影；设置界面是否使用了 settings 区块；仅 token 模式下是否误装了 marchen-design 的组件。

#### 场景: 手写了已有组件

- **GIVEN** 页面中用 div 和 class 手写了一个"开关"
- **WHEN** 运行 design-review
- **THEN** 结果指出应改用 switch 组件

### 需求: 输出形式

审查结果 MUST 按严重程度分组列出问题，每条包含位置、违反的规则和具体修改建议；没有问题时 MUST 明确说明通过。审查 MUST NOT 在用户未要求时直接修改代码。

#### 场景: 没有问题

- **WHEN** 审查范围内没有违规
- **THEN** 输出"通过"以及检查过的文件列表

### 需求: lint 脚本可独立运行

lint-design 脚本 MUST 保持零依赖，可在任意项目中以 `node <脚本路径> <文件或目录>` 运行，并与仓库自身使用的是同一份。

#### 场景: 在用户项目中运行

- **GIVEN** 一个没有安装任何额外依赖的项目
- **WHEN** 运行插件中的 lint-design 脚本扫描 `src/`
- **THEN** 正常输出结果
