## 目的

用自动化检查保障设计规则、生成物一致性、安装链路和视觉表现，取代手工验证，并聚合为一条命令。

### 需求: 设计规则检查

系统 MUST 提供设计规则检查命令，扫描 registry 源码中的禁用写法，至少包括：渐变、彩色的 indigo / violet / purple 等装饰色类、用于非浮层元素的大阴影（shadow-lg 及以上）、手形指针、毛玻璃（backdrop-blur 用于内容层）。发现违规时 MUST 失败，并给出文件、行号和违规写法。plugin 的审查功能 MUST 使用同一份检查逻辑。

#### 场景: 发现渐变

- **GIVEN** 某组件源码中包含 `bg-gradient-to-r`
- **WHEN** 运行设计规则检查
- **THEN** 命令以非零状态退出，输出该文件的路径、行号和 `bg-gradient-to-r`

#### 场景: 浮层允许阴影

- **GIVEN** 弹层组件的弹出层使用了中等阴影
- **WHEN** 运行设计规则检查
- **THEN** 不报告违规

#### 场景: 检查任意目录

- **WHEN** 对一个外部项目的目录运行设计规则检查
- **THEN** 按同样的规则输出该目录中的违规

### 需求: 生成物一致性

系统 MUST 能检测生成物是否与源头同步：重新生成后，若生成物与仓库中已提交的内容不同，检查 MUST 失败，并列出不一致的文件。

#### 场景: 改了 token 忘记重新生成

- **GIVEN** 源头中的 token 已修改，但没有重新生成
- **WHEN** 运行一致性检查
- **THEN** 命令失败，列出过期的生成文件

### 需求: 冒烟测试

系统 MUST 提供冒烟测试，在隔离的临时目录中自动完成以下流程：构建并在本地提供 registry；用 base 初始化新 Vite 项目；校验核心组件已安装且项目编译通过；按命名空间安装一个条目；在一个未配置命名空间的项目中按地址安装一个条目；安装一个强调色条目并校验变量已变化。任一步失败时 MUST 指出是哪一步。测试结束后 MUST 清理临时目录和本地服务。

#### 场景: 全部通过

- **WHEN** 在 registry 正常的情况下运行冒烟测试
- **THEN** 每一步都通过，命令以零状态退出
- **AND** 没有残留的本地服务进程

#### 场景: 某一步失败

- **GIVEN** base 条目引用了一个不存在的组件
- **WHEN** 运行冒烟测试
- **THEN** 命令失败，并指出失败的是初始化这一步

### 需求: 截图回归

系统 MUST 能遍历所有 story 的所有矩阵格子并截图，与已保存的基准图比较。存在差异时 MUST 列出有差异的格子，并输出差异图。系统 MUST 支持把当前截图更新为新的基准。

#### 场景: 修改 token 后发现变化

- **GIVEN** 已有基准截图
- **WHEN** 修改了深色模式的 card 颜色后运行截图比较
- **THEN** 列出所有包含 card、且为深色的格子

#### 场景: 更新基准

- **WHEN** 以更新模式运行截图
- **THEN** 当前截图成为新的基准，之后再比较时没有差异

### 需求: 聚合检查命令

系统 MUST 提供一条聚合命令，依次执行：生成物一致性、registry 依赖校验、设计规则检查、类型检查、代码规范检查和 registry 构建。冒烟测试和截图回归耗时较长，SHOULD 作为单独的命令提供，不包含在聚合命令中。

#### 场景: 一条命令完成日常检查

- **WHEN** 在干净的仓库中运行聚合检查命令
- **THEN** 依次执行上述各项检查并全部通过
