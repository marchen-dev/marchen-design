## 目的

提供设置界面的区块：布局外壳、分组、设置行和设置弹窗。使用者只需组合，层级、对齐、焦点等细节由区块保证，弹窗和页面两种形态都能使用。

### 需求: 设置行

设置行 MUST 左侧显示名称和可选的一行说明，右侧放控件，控件 MUST 与名称在垂直方向居中对齐（无论是否有说明）。名称 MUST 与右侧控件关联：点击名称时聚焦或切换对应的控件，辅助技术能读出控件的名称。使用者 MUST NOT 需要手动设置 id 来完成关联，但 MAY 显式指定。

#### 场景: 有说明时仍然居中

- **WHEN** 渲染带说明的设置行"开机启动"，右侧为开关
- **THEN** 开关在整行高度内垂直居中，而不是与名称顶部对齐

#### 场景: 点击名称切换开关

- **GIVEN** 一个右侧为开关、未手动指定 id 的设置行
- **WHEN** 点击名称文字
- **THEN** 开关的状态切换

### 需求: 设置分组

设置分组 MUST 在卡片外显示小号、次要颜色的分组标题，卡片内依次放置设置行。行与行之间 MUST NOT 有分隔线，只靠行高区分。分组 MAY 带一行分组说明。

#### 场景: 分组外观

- **WHEN** 渲染标题为"行为"、包含两行设置的分组
- **THEN** "行为"显示在卡片上方、卡片外
- **AND** 两行之间没有分隔线

### 需求: 设置外壳布局

设置外壳 MUST 由左侧导航区和右侧内容区组成。内容区 MUST 使用 background 层底色，使其中的卡片在明暗两种模式下都比底色亮；内容区 MUST 可以独立滚动，标题区和底部操作区 MUST 固定不随内容滚动。外壳 MUST NOT 依赖特定的外层容器，放在弹窗或页面中都能工作。

#### 场景: 深色下卡片比底色亮

- **GIVEN** 深色模式
- **WHEN** 在设置外壳的内容区放置一个分组
- **THEN** 分组卡片的底色比内容区底色亮

#### 场景: 内容较多时滚动

- **WHEN** 内容区的分组总高度超过可用高度
- **THEN** 只有内容区滚动，标题和底部操作按钮保持可见

#### 场景: 放在页面中

- **WHEN** 把设置外壳直接放在页面布局中（不使用弹窗）
- **THEN** 布局正常，高度跟随父容器

### 需求: 设置弹窗

设置弹窗 MUST 组合弹窗与设置外壳，提供固定的默认尺寸（宽约 840px、高约 600px，在小视口下不超出屏幕）。弹窗打开时，初始焦点 MUST 落在内容区，MUST NOT 落在第一个导航项上。弹窗 MUST 有可供辅助技术读取的标题。

#### 场景: 打开时的焦点

- **WHEN** 打开设置弹窗
- **THEN** 第一个导航项没有焦点环
- **AND** 按 Tab 后焦点进入内容区中的第一个可交互元素或导航（按文档顺序）

#### 场景: 小视口

- **GIVEN** 视口宽度只有 600px
- **WHEN** 打开设置弹窗
- **THEN** 弹窗宽度不超过视口，左右留有边距

### 需求: 只依赖 marchen-design 的组件

设置区块 MUST 只依赖 marchen-design 提供的组件和区块（卡片、field、弹窗、sidebar-nav 等），registry 依赖 MUST 使用命名空间形式，安装时 MUST NOT 把用户项目中的 marchen-design 组件替换成上游版本。

#### 场景: 安装不覆盖已有组件

- **GIVEN** 一个用 base 初始化的项目
- **WHEN** 安装 `@marchen-design/settings`
- **THEN** 项目中的 button、card 等组件仍是 marchen-design 版本
- **AND** 新增 `components/settings.tsx` 和 `components/sidebar-nav.tsx`，项目编译通过

### 需求: 两种形态的 demo

预览站 MUST 提供设置弹窗和设置页面两个 demo，均只用区块组合而成，并纳入截图回归。

#### 场景: demo 覆盖两种形态

- **WHEN** 打开预览站的 demos 区
- **THEN** 能看到设置弹窗和设置页面两个 demo，且都能在「明暗 × 强调色」下渲染
